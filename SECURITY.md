# Безопасность

## Как сообщить об уязвимости

Если вы нашли уязвимость в Касса API, не создавайте публичный Issue. Напишите на **aibolkazbayev@gmail.com** с темой «Касса API security»: что нашли, как воспроизвести, чем это грозит. Отвечу в течение трёх дней.

## Что сделано

- Пароли — scrypt с солью; слабые и популярные пароли не принимаются; пароль проверяется и для несуществующего email — по времени ответа не узнать, кто зарегистрирован.
- Вход — не больше 5 попыток в минуту на пару «IP + email»; регистрация — 10 в час с одного IP (`@fastify/rate-limit`).
- Заголовки безопасности на каждом ответе: CSP, HSTS, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy.
- Роли: создавать и отменять события может только организатор; чужие заказы выглядят как несуществующие.
- Вебхуки платёжного сервиса проверяются по HMAC-подписи сырого тела, старые подписи (старше 10 минут) отклоняются.
- Idempotency-Key: повтор запроса не создаёт второй заказ; токен в журнале скрыт (`redact`).
- Ошибки 500 без подробностей, только ID запроса — он же в заголовке `X-Request-Id` каждого ответа.
- Каждый CI: npm audit (уязвимые зависимости), CodeQL (анализ кода).
- Тесты: `tests/api/hardening.test.ts`, `tests/unit/security.test.ts`.
