# Чек-листы ручной проверки «Кассы»

Проверка через Swagger: [документация онлайн](https://kassa-api-419n.onrender.com/docs) или `http://localhost:3000/docs` локально. Демо-аккаунты: `organizer@kassa.kz` и `buyer@kassa.kz`, пароль `kassa-demo`. Токен из ответа `/auth/login` вставляется в кнопку **Authorize**.

## Смоук после деплоя — 5 минут

- [ ] `GET /health` отвечает `{"status":"ok"}` (первый запрос может идти до минуты — сервер просыпается)
- [ ] `GET /events` — афиша с событиями, у каждого реальное число свободных мест
- [ ] Покупатель входит, держит 2 места через `POST /events/{id}/holds`
- [ ] `POST /orders` с заголовком `Idempotency-Key` создаёт заказ, сумма равна сумме цен мест
- [ ] `POST /orders/{id}/pay` с `tok_success` — через пару секунд заказ в статусе `paid`
- [ ] В `GET /events/{id}/sales` у организатора видна продажа

## Регресс перед релизом

### Вход и права

- [ ] Неверный пароль и несуществующий email дают одинаковый ответ
- [ ] Шестая попытка входа за минуту — `429`
- [ ] Покупатель не может создать событие, организатор не может бронировать
- [ ] Чужой заказ и чужое событие — `404`

### События

- [ ] Организатор создаёт событие из секторов, зал собирается правильно
- [ ] Прошедшее событие нельзя опубликовать
- [ ] Черновик, отменённое и прошедшее событие не продаются
- [ ] Афиша листается по курсору без пропусков и повторов

### Бронь и заказ

- [ ] Занятое место — `409` со списком мест, которых не хватило
- [ ] Больше 10 мест разом — ошибка
- [ ] Повторная бронь своих мест продлевает её
- [ ] Через 10 минут бронь освобождается, место снова свободно
- [ ] Повтор `POST /orders` с тем же ключом возвращает тот же заказ; другое тело с тем же ключом — `422`
- [ ] Отмена заказа освобождает места

### Оплата и вебхуки

- [ ] `tok_declined` — заказ ждёт, видна причина отказа, можно оплатить другой картой
- [ ] Повтор «Оплатить» с тем же ключом не создаёт второй платёж
- [ ] Просроченный заказ оплатить нельзя
- [ ] Вебхук без подписи или с изменённым телом — `400`, заказ не меняется
- [ ] Отмена события организатором: оплаченные заказы возвращаются, брони снимаются

### Ответы API

- [ ] Битый JSON — `400`, id вне диапазона — `422`, а не `500`
- [ ] У каждого ответа есть заголовок `X-Request-Id`
- [ ] Ошибки в одном формате, текст понятен без чтения кода
- [ ] В Swagger у каждого эндпоинта есть описание и пример
